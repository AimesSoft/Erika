# 播放器自定义阴影性能记录

2026-10-22。对应当前播放器：视频尺寸固定，原生液态玻璃按钮不加额外阴影；文字、时间轴、普通图标、输入框与设置面板底板保留阴影。

## 测量条件

- MacBook Air，Apple M4（10 核 CPU / 8 核 GPU），16 GB，macOS 27.0.1。
- 本地 Debug 构建（Swift `-Onone`），1258 × 758 点窗口、2 倍像素密度。
- 同一独立预览程序、同一 1280 × 720 / 10 fps 明亮网格视频，Pure 预设；没有弹幕、外部字幕或画质增强负载。
- 只在 `target/player-overlay-v3/profile` 内的生成代码加入启动开关，切换五项播放器样式的自定义阴影（3 点模糊、向下 1 点、黑色 0.9）。关闭组仍保留系统原生玻璃效果。正式源码和正式 App 没有测试开关。
- 先播放 4 秒完成预热，再暂停 4 秒。每个场景稳定 2 秒后测量 8 秒；交替顺序为关闭、开启、开启、关闭、关闭、开启。动画场景每秒切换一次设置面板。
- CPU 使用 `proc_pid_rusage` 的进程累计 user/system time，按本机 `mach_timebase_info = 125/3` 换算为纳秒。100% 表示一个 CPU 核；内存为进程 physical footprint，不是单独的 GPU 纹理内存。
- 采样前后均记录窗口位置与焦点。排除任一端不在前台的样本；启动预热不一致的早期试采也未采用。保留样本仍较少，不能当作统计显著的性能结论。

## CPU 与内存

下面是保留的实际范围，括号内为样本数。它们是整个播放器的占用，不是阴影本身的占用。

| 场景 | 关闭自定义阴影 CPU | 开启自定义阴影 CPU | 关闭 / 开启的 physical footprint |
| --- | --- | --- | --- |
| 暂停，控件静止显示 | 6.80%–6.99%（2） | 6.72%–7.36%（2） | 168.1–174.2 / 167.8–169.0 MiB |
| 播放，设置面板展开 | 13.12%–13.28%（2） | 11.68%（1） | 174.2–176.6 / 174.2 MiB |
| 暂停，反复开关设置面板 | 25.11%–25.59%（2） | 24.53%（1） | 191.2–194.6 / 194.8 MiB |

没有测出稳定的 CPU 或进程内存增量。开启组部分数值更低并不说明阴影让程序更快；窗口调度、系统负载与样本数量会影响结果，不能据此给出固定百分比，也不能认定零开销。

## GPU 追踪的限制

Metal System Trace 可以采集到当前进程的 GPU 活动及 WindowServer 的合成活动，但这轮没有得到同条件的有效 GPU 配对：关闭阴影的录制前后窗口均不在前台，开启组因窗口尚未就绪而中止。因此不提供“阴影额外耗时多少毫秒”或 FPS 损失的数值，也不把整机 WindowServer 的活动算作本播放器的阴影成本。

CPU 表格测量的是上述最终投影范围。随后四个侧边播放图标由不透明浅灰改为不透明纯白，投影半径与范围不变；该颜色调整未重新跑性能测量。

## 成本来自哪里

阴影会增加模糊、透明混合以及可能的中间纹理分配；实际工作量取决于投影面积、模糊半径、像素密度、更新频率和系统缓存方式。SwiftUI 可以合并或缓存绘制，所以不能把控件数量直接当作 GPU pass 数量，也无法用总耗时简单除以控件数得到单个控件成本。

控件静止时可以复用已绘制内容；拖动、淡入淡出、缩放和布局动画期间更可能重新绘制或合成。控件隐藏后，对应视图被移除；中央提示的阴影也随提示一起移除。视频解码、字幕和弹幕的渲染不经过控件阴影。

这次取消了玻璃控件外层的额外投影，避免对本身已有材质效果的控件重复处理。标题和时间轴按小范围分组，普通图标单独投影，中央反馈的阴影范围为 88 × 88 点。保留 3 点半径，没有引入全屏模糊、全屏遮罩或逐帧截图。
