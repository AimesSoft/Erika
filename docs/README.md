界面设计见 [design/index.html](../design/index.html)，交互原型见 [design/app.html](../design/app.html)。这里记录用 Bern 实现时的技术决定。

## 工程结构

```text
Bern.toml              应用清单：语言、外壳、模块、构建目标
erika-protocol/        核心的协议：打开、播放控制、设置、模块开关
erika-core/            核心的引擎：播放、设置、账号、最近播放与弹幕匹配
erika-store/           设备上保存的东西：一个 SQLite 数据库（地址、文件、剧集、进度）
erika-dandanplay/      弹弹play：经 NipaPlay 的网关登录、新番、详情、匹配、弹幕、搜索
erika-torrent/         BT 下载：librqbit 的会话、读种子、增删任务、边下边播的本地流
erika-ui/              外壳界面：窗口、侧栏、播放层、纯粹模式、设置、首次启动
modules/<模块>/         可选模块，各有 protocol、core、ui 与 Bern.toml
docs/                  技术文档
design/                界面设计文档与原型
```

## Web 运行

项目提供两个独立目标：`web_ui` 是连接原生引擎的 **WebUI**；`web_app` 是将引擎编译进页面 WASM 的**纯 Web 应用**。`ui = "web"` 选择网页渲染器，`web_mode` 决定引擎在哪里运行。

### WebUI（独立引擎）

在 Erika 根目录执行：

```sh
cargo build --manifest-path ../Bern/Cargo.toml -p bern-cli
../Bern/target/debug/bern build --target web_ui --release
target/bern/web_ui/bin/erika-host --port 4174
```

打开宿主打印的完整 `open http://127.0.0.1:4174/#token=…` 地址。`erika-host` 同时提供网页和 `/bern` WebSocket 通道；业务引擎在这个原生进程内运行。页面中的 WASM 只包含界面会话与协议客户端。保持宿主运行，Ctrl-C 停止服务。

产物位于 `target/bern/web_ui/`，其中 `bin/` 包含宿主、CLI 和 MCP 程序。也可用 `../Bern/target/debug/bern run --target web_ui --release` 构建并自动选择端口。固定端口由 `erika-host --port` 指定。

WebUI 的本地视频使用 liberika 浏览器播放扩展：文件留在选取它的网页中解码，原生 Erika 引擎通过同一条 WebSocket 下发播放命令并接收进度、轨道和操作结果。打开文件、暂停、跳转、字幕、弹幕与截图沿用现有播放器；截图下载到浏览器。文件名先登记给引擎，多页面按文件归属执行播放。重新打开网页后需重新选择本地文件。构建需要与 `web_app` 相同的 liberika Web 工具链，详见 [浏览器播放](web-playback.md#webui-本地播放)。

2026-10-23 在 macOS arm64 完成 Release 构建与启动验证：网页显示引导，控制台无启动错误，CLI 能读取原生引擎状态并列出该网页的会话；生成记录为 `web_mode: ui`、`engine_deployment: engine-host`、`application_transport: websocket`，页面 crate 不依赖 `erika-core`。构建时补齐了相邻 liberika 的 `erika_ffmpeg_sys/build.rs` 对 macOS Clang 运行库的链接，解决独立 Rust 宿主缺少 `__isPlatformVersionAtLeast` 的错误。

### 纯 Web 应用（浏览器内引擎）

[纯 Web 播放与部署](web-playback.md) 包含 `web_app` 的播放适配、发布包和独立验证步骤。

使用包含本次 Web 后端扩展的相邻 Bern 仓库。在 Erika 根目录执行：

```sh
cargo build --manifest-path ../Bern/Cargo.toml -p bern-cli
../Bern/target/debug/bern run --target web_app --port 4173
```

访问 `http://127.0.0.1:4173/`，Ctrl-C 停止开发服务器。首次构建需要 liberika 的 Web 工具链（Emscripten、wasm-bindgen 等，见 [浏览器播放](web-playback.md)）及 Rust 的 `wasm32-unknown-unknown` 目标：

```sh
rustup target add wasm32-unknown-unknown
```

只构建静态文件：

```sh
../Bern/target/debug/bern build --target web_app --release
```

产物位于 `target/bern/web_app/`；通过 HTTP(S) 提供其中的 HTML、JavaScript、CSS、WASM、`resources/` 和 `extension/`，不要直接双击 HTML。Rust 引擎在浏览器的 WASM 内运行，不需要原生 Erika 进程，也不连接 macOS 的 CLI/IPC 会话。

引导完成状态、模块选择和主题按站点 origin 与应用标识保存在浏览器 localStorage。开发时保持同一个地址和端口；切换端口、浏览器或清除此站点数据会得到独立配置。原生 macOS 的配置不受影响。界面继续使用同一套 Bern 声明。`web_app` 已接入 liberika 的真实视频、字幕和弹幕播放；下载、账户服务和其他桌面功能的适配范围见 [浏览器播放](web-playback.md)，不能据此视为全部可用。

2026-10-15 的首轮 Chromium 检查覆盖 1280 × 800 桌面与 390 × 844 窄屏的引导、设置、搜索、媒体库、周历和模拟下载。窄屏引导正文滚动、底部按钮固定，进度圆点单独一行；设置窗口占满应用栏下方区域。这轮检查及逻辑测试未发现后续 Safari 实测暴露的滚动、尺寸和选中色问题，不能作为完整 Web 验收。

随后使用真实 Safari 27.0.1 验证并修复普通滚动区误用居中停靠、查询内容高度链断开、深层图片撑宽祖先及侧栏选中前景色配对问题。2026-10-16 复查确认媒体库显示 16 张海报，筛选「未看」得到 8 张；首页工具栏和右栏回到视口内，周历周一切换周三、设置通用切换外观均正常。侧栏最初只修复了可读性，仍错误使用灰色选中背景；再次修正后，Safari 深色绯红的主侧栏与设置侧栏均使用强调色实底，Chromium 另验浅色荧绿、浅色群青及选中/悬停状态。macOS 的原型配色通过目标样式保留。

Rail 放大图片画框的问题也已修复：Safari 在 1470 CSS px 宽度下确认舞台图右侧圆角和 28 px 间距恢复；Chromium 1470 × 754 下舞台按钮与图片均为 528 × 297。媒体库窄屏工具栏已修复，Chromium 390 × 844 和 360 × 780 下标题不换行、完整缩放控件两端可见、网格正常，页面没有横向溢出；这两项仅验证媒体库布局。Safari 手机布局及 Firefox 尚未实测。详细原因与验证范围见 [Web app 适配补充](bern-extensions.md#web-app-适配补充2026-10-15)。

## 播放内核 liberika

播放由 [liberika](https://github.com/AimesSoft/liberika) 完成，代码在 `erika-core/src/kernel/`：`kernel.rs` 是引擎看到的接口（打开、播放、跳转、轨道、截图等），`kernel/liberika.rs` 把 liberika 做成 Bern 的媒体内核。liberika 自己的线程为每个播放器持有一个 `PresenterRuntime`，在 `Video` 视图给出的 `CAMetalLayer` 上按显示刷新绘制画面、字幕和弹幕，没有视图时继续推进音频；它把播放状态报告给 Bern 的媒体中心（命令行 `erika media state --player-id video` 能看到同一个播放器），引擎在 250 ms 的播放节拍里读取位置、时长、轨道与结束状态。播放 3 秒后、暂停与缩小时截一张画面（480 宽 PNG，存在缓存文件夹的 `stills/`），作为迷你播放器、转场和最近播放的静帧。「更多 › 截图」（⌘S）按视频原尺寸把画面连同字幕存到「图片 › Erika」，文件名是标题加画面所在时间。

本地构建先准备 liberika 的原生依赖（FFmpeg、dav1d、libass 等，静态编译，一次即可）：

```sh
brew install cmake meson ninja nasm pkg-config
ERIKA_LIBERIKA_ROOT="$(python3 web/dependencies.py)"
cargo run --manifest-path "$ERIKA_LIBERIKA_ROOT/Cargo.toml" -p xtask -- \
  deps build --all --profile lgpl --target aarch64-apple-darwin
```

**字幕与弹幕都由 liberika 画在画面里**（2026-10-21），Erika 不再自己绘制：字幕是文件内嵌或外挂的轨道，字号对应 liberika 的字幕缩放；弹幕来自与视频同名、同目录的 `.xml` / `.json`（打开视频时自动加载）、播放设置或设置窗口里「挂载」的 B 站 xml 与弹弹play json，以及自己发送的弹幕（作为一条单独的轨）。弹幕设置存在引擎状态 `danmaku_settings` 里，按 liberika 的参数换算：字号滑块 20–40 点（中间 30），速度滑块是滚过画面的 14–6 秒，显示区域四分之一、一半、全屏，另有不透明度、合并重复、屏蔽顶部 / 底部 / 滚动和整体偏移。

**只接 liberika 支持的功能**：liberika 没有的就删掉入口，不在 Erika 里模拟，也不为此改 liberika。因此删去了字幕延迟、音频延迟、画面亮度、画面比例、HDR 开关（liberika 只在创建时选输出模式；设计稿本就写 HDR 自动启用、不提供开关）、屏蔽彩色弹幕和画中画；画面分页只在画质增强模块打开时出现，里面是超分辨率。弹弹play 匹配不是内核功能，由外壳在打开视频时请求（见下面的「存储与弹弹play」），面板里列出实际挂载的弹幕来源。模块里的示例剧集没有字幕和弹幕。

之后照常 `bern build --target macos`。Bern 会把 liberika 需要的系统框架（Metal、VideoToolbox、CoreAudio 等）交给 swiftc 链接。

目前只有 macOS 接了 liberika：iOS、tvOS 的视图已由 Bern 生成，需要先为模拟器编译 liberika 的依赖再实测；Windows、Linux、Android 等 Bern 给出 D3D、Wayland/X11、Android 的表面后接入；Web 上 liberika 没有播放后端。没接的平台仍按剧照模拟播放。没接的平台没有字幕和弹幕。

## 存储与弹弹play（2026-10-21）

按设计稿的存储方案（issue #867 的三层模型）落地，代码在 `erika-store/`：数据库是数据文件夹（`bern::storage::data_dir()`，macOS 上是 `~/Library/Application Support/com.aimessoft.erika/erika.db`）里的一个 SQLite 文件。

- **地址 → 文件 → 剧集**：地址是来源加路径（直接打开的视频属于来源 1，路径是它的 URL）；文件是前 16 MiB 的 MD5 加文件大小，同一个视频挪了地方或有副本仍是同一个文件；文件连到弹弹play 的剧集，剧集属于番剧，两者都按弹弹play 的 ID 存。
- **进度跟文件，看过跟剧集**：观看进度存在文件上，换个地方打开同一个视频会接着播；「最近播放」记地址和截图，截图在缓存文件夹的 `stills/`。
- **缓存放文件**：新番列表（`dandanplay-season.json`）和 bangumi-data 的播出时刻（`bangumi-schedule.json`）在缓存文件夹，下次启动立刻显示，再到后台刷新。
- **令牌进钥匙串**：弹弹play 的令牌存在系统凭据库（`bern::secrets`），数据库里只有用户名和昵称；三周后自动续期（`GET /api/v2/login/renew`，POST 会被回 405）。昵称取登录与续期回答里和令牌并列的 `screenName`；还以登录名为昵称的账号启动时续期一次，顺带取回昵称。
- 外壳与每个模块各开一个连接，迁移按版本号只跑一次。浏览器没有数据库文件，只保留当次会话。

弹弹play 的代码从 NipaPlay 移植（`erika-dandanplay/`）：请求经 NipaPlay 的网关（香港 `nipaplay.aimes-soft.com` 优先，失败时用国内备用），签名与登录哈希与 NipaPlay 相同，网关替换 AppSecret；除登录外都要带令牌。

- **账号**：设置 › 账号（手机在设置首页的账号行）登录或退出；侧栏底部显示昵称。
- **匹配**：打开视频时算出文件指纹；已登录就请弹弹play 按文件名和指纹匹配，认出后把文件连到剧集，播放器标题换成番名与集数，并自动加载这一集的弹幕（转成 liberika 能读的 JSON）。
- **追番模块**：新番来自弹弹play 的新番列表，播出时刻来自 [bangumi-data](https://github.com/bangumi-data/bangumi-data)（按名字对上：弹弹play 新番列表里的 `bangumiId` 是它自己的编号，不是 Bangumi 的；名字先比全名，再把季数「第二期 / 第2季 / (第3期)」、「续篇」「新作动画」和括号里的年份拆开比，最后才比开头，宽松的比法只在弹弹play 给的星期里只有一部对上时才算；换算成本地时间，凌晨的算前一天的深夜）；对不上的只按星期列在当天最后，不进时间轴。番剧详情、剧集与搜索来自弹弹play。首页时间轴是弹性的：同一时刻并排成组、组下一根茎落到尺上的点，间距随时间差在 16 到 64 点之间，两小时以上的空档画「⋯」，轨道至少 900 点（大窗口 1120）并按时间分配多出的长度，放不下就横向滚动；位置由引擎算好（`modules/anime/core/src/timeline.rs`）。「继续观看」是播过并认出的视频，一部番一行；剧集胶片标出哪些集有文件、看到哪里，点有文件的集直接播放，没有文件的提示先打开它的视频。详情里原来不起作用的「更多」菜单和分页去掉了。
- **媒体库模块**：按设计稿分「番剧」和「来源」两段。番剧墙列出有文件、已认出的番，按拼音首字母进索引；有几个来源时，筛选条后面多一排来源选择（`Menu` 里不能放 `ForEach`，所以没用设计稿的下拉菜单）。来源里添加本地文件夹（电视上没有选文件，不显示添加），列出每个来源的文件数和扫描进度，下面是「没认出的文件」；点开来源一层层浏览文件夹，每个文件写着认成了哪一集，可以重新匹配、解除匹配，文件夹可以批量匹配。
- **扫描**：移植 NipaPlay 的扫描（`file_scan.rs` 与 `ConcurrentVideoProcessor`，代码在 `modules/library/core/src/scan.rs`）：遍历文件夹找视频（跳过隐藏的文件和文件夹、不跟随链接，扩展名按 liberika 能播的容器），只重新读大小或修改时间变了的文件、算指纹，再四个一组请弹弹play 匹配没认出的文件；读文件和问弹弹play 都在别的线程，结果交回引擎写库。添加时、每次启动时和「重新扫描」时扫描；文件夹里删掉的文件随扫描从库里去掉，找不到文件夹（比如移动硬盘没接）时保留原来的记录、来源显示找不到。弹弹play 的匹配只给番名不给海报，墙上没有海报的番会再取一次详情补上。
- **手动匹配**：照设计稿的两种配法。按文件名里的集数（`names.rs` 认 `- 01`、`[01]`、`第01话`、`S01E02`、`EP01`，跳过年份和 1080p 这类数字），名字里的集数超过这部番的总集数时自动「对齐」到第 1 话，也可以手改；没有集数时按顺序从第几话开始配。点某一行的集数原地改（Bern 的输入框只能写会话草稿，所以一次改一行），左边的勾跳过一个文件，「要看一下」只列跳过的、没有集数的、超出的和同一话的几个版本。番剧用弹弹play 搜索，打开匹配时先按文件夹名或文件名搜一次。确定后在一个事务里写入，出错就全部不改；手动匹配和解除匹配都记下来，以后的自动匹配不再改它们。匹配或移除后媒体库发 `files_changed` 事件，外壳转告追番模块刷新（媒体库或新番开启时保留追番模块，二者都关闭时才停用）。
- 没登录时，首页和新番页读取服务器每日更新的公开缓存（含简介和缓存海报），退出登录也保留已有新番；媒体库照样扫描，扫描完提示登录后才能自动认出番剧。
- 番剧详情显示最新 20 条短评：未登录读取服务器当日的弹弹快照；登录弹弹play 后由客户端即时拉取；登录 Bangumi 时优先客户端直连 Bangumi，两种账号都登录也优先 Bangumi。刷新期间保留本地旧评论，首次没有缓存时并行请求弹弹作为临时内容；Bangumi 失败则回退弹弹。有效的空评论响应不视为故障，迟到请求不会覆盖另一部番或新的账号状态。服务部署与图片源配置见 `server/anime-cache/README.md`。
- **下载**：移植 NipaPlay 的下载器（`rust/src/api/torrent.rs`，librqbit 8.1.1），代码在 `erika-torrent/`：每个进程一个 librqbit 会话，任务存进数据文件夹的 `torrents/`，下次启动接着下（fast resume）；磁力链接从网络上读出种子、.torrent 文件直接读，先列出文件、大小和建议的文件夹名再添加；暂停、继续、移除（保留文件）、删除任务和文件（先确认）；没下完的视频经 127.0.0.1 上的小 HTTP 服务器按字节范围边下边播，下完的按本地文件播放，所以能认出剧集、带弹幕。下载模块（`modules/downloads/`）用页面的时钟每秒读一次进度；默认存到「下载/Erika」（没有下载文件夹的手机上存进数据文件夹），可以改，用过的文件夹在「快速选择」里；默认每个任务一个文件夹。下载完成时提示，并（默认开启）发 `downloads::finished` 事件，外壳把下载到的文件夹交给媒体库当来源扫描。浏览器和电视上没有下载器，页面会说明，不显示添加；电视的构建不带 librqbit。NipaPlay 下载页的搜索、排序、网格视图和「打开文件夹」没有搬：设计稿的下载页是分「进行中 / 已完成」的行，Bern 也还没有在访达里显示文件的能力。
- 仍是示例的：插件市场；状态与评分只在本次运行内有效。

## 电视剧与电影：内置的识别服务器（2026-10-24）

弹弹play 只认番剧。电视剧和电影由 Erika 自己服务器上的两样东西认，地址内置在 Erika 里，用户什么都不用填：[Misaka 弹幕服务](https://github.com/l429609201/misaka_danmu_server)（兼容弹弹play 接口，按文件名匹配，接 TMDB、豆瓣等资料，从各视频网站取弹幕）和它前面的指纹网关（`erika-gateway/`，Rust）。两者都不用文件指纹，指纹由网关补上：

- 网关讲弹弹play 的接口，路径是 `/{钥匙}/api/v2/…`。`match` 先查指纹表（前 16 MiB 的 MD5 加大小 → Misaka 的作品与集），查到就直接回答，查不到再交给 Misaka；新增 `match/confirm` 记下确认的匹配、`match/forget` 忘掉解除的匹配；其余请求原样转给 Misaka。Misaka 重新导入、编号变了时，按片名和集数找回原来那一集。
- 两把钥匙：服务器主人的令牌（`ERIKA_GATEWAY_TOKEN`，确认的结果所有设备都信，解除时连别人的确认一起清掉，不限流），和内置在 Erika 里的公开钥匙（`ERIKA_GATEWAY_PUBLIC_KEY`，写在 `erika-dandanplay/src/custom.rs` 的 `BUILT_IN`）。公开钥匙下，每台设备凭 `X-Erika-Device`（Erika 第一次启动时随机生成，存在设置 `device.id`）各投各的票：自己确认过的文件回答自己的选择，没确认过的回答主人的选择，没有就回答多数设备的选择；解除只撤回自己那一票。每台设备每分钟 120 次请求（`ERIKA_GATEWAY_PER_MINUTE`），同一来源地址合计十台设备的量，挡住自己换设备号刷请求的。换钥匙会让旧版 Erika 连不上（它们会提示更新）。
- Misaka 的几处脾气，网关替客户端抹平：它自己的作品编号要写成 `bangumi/A<编号>`（纯数字会被当成 bgm.tv 的编号），网关转发时补上 `A`；后备匹配与后备搜索给的作品编号是临时的（900000 起，过一阵就指向别的剧），集编号却是长久的（`25` + 作品 6 位 + 来源 2 位 + 集数 4 位），所以匹配与详情的回答一律换成从集编号算出的长久作品编号，详情标题去掉「（来源：…）」，确认时也按集编号记；长久编号的详情只列已经取过弹幕的集，网关记下经手过的每部剧的详情（`show` 表），把见过的集补回去；第一次取某集弹幕时 Misaka 等视频网站 30 秒就先回空、在后台继续取，网关见到等了 20 秒以上的空回答会每 4 秒再问一次，最多 4 次。Erika 的两个手动匹配（媒体库与播放器）按请求时的编号认领详情，再改用详情里的长久编号。
- Erika 这边：来源分「番剧 / 电视剧 / 电影」，番剧照旧走弹弹play，电视剧和电影走识别服务器（`erika-dandanplay/src/custom.rs`）；它的编号在 Erika 的数据库里存成负数，`details` 与 `comments` 遇到负数就去识别服务器取，所以详情页和弹幕不用改。媒体库与播放器里的手动匹配、解除匹配都会告诉网关。设置里没有识别服务器的入口；早先手填版存在钥匙串里的地址（`match-server`）启动时会删掉。引擎自己的测试不连服务器。
- 下载器顺带修了：librqbit 默认把 DHT 状态（含端口）存在所有程序共用的文件里，NipaPlay 开着时 Erika 的下载起不来；现在 DHT 状态放在 Erika 自己的会话文件夹里。

部署在 `43.142.85.190`（与 NipaPlay 的国内备用网关同一台，1 GB 内存）：

- Misaka 用 Docker 跑，只监听 `127.0.0.1:7768`，内存上限 400 MB；数据库是同机的 PostgreSQL 容器（`127.0.0.1:5432`，上限 160 MB）。Misaka 的代码只支持 MySQL 与 PostgreSQL（模板里写的 SQLite 不能用）。
- 网关是 systemd 服务 `erika-gateway`（用户 `erika`，`127.0.0.1:7769`，上限 64 MB，数据在 `/var/lib/erika-gateway/`，配置在 `/etc/erika-gateway.env`）。用 `cargo zigbuild -p erika-gateway --release --target x86_64-unknown-linux-musl` 交叉编译成静态程序再传上去。
- nginx 的 `nipaplay.conf` 只加了一条 `location ^~ /erika/`，不记访问日志（令牌在路径里）；其余规则没动。
- 服务器上的 `/opt/erika/`：`secrets.env`（数据库密码、Misaka 初始管理员密码、网关令牌，只有 root 能读）、`set-misaka-token`（写入在 Misaka 里建的 API 令牌并重启网关）、`erika-address`（打印主人用的地址）、`misaka-admin`（打印 Misaka 管理员账号）。
- Misaka 要能认出没见过的剧，得开「后备匹配」「后备搜索」（`matchFallbackEnabled`、`searchFallbackEnabled`），还得装弹幕源：新版 Misaka 的弹幕源（bilibili、iqiyi 等 `.so`）不在镜像里，要从资源仓库 `l429609201/Misaka-Scraper-Resources` 下载。服务器在国内，连不上 github.com 与 raw.githubusercontent.com，所以资源仓库设成 jsDelivr 镜像 `https://cdn.jsdelivr.net/gh/l429609201/Misaka-Scraper-Resources@main`，并打开弹幕源自动更新（每 30 分钟查一次，按清单里的 SHA-256 校验）。`api.themoviedb.org` 也连不上，TMDB 地址改成能连上的 `https://api.tmdb.org`。
- 现在只有 80 端口、没有域名，请求以明文走 HTTP；有域名后应加 HTTPS，并把 `BUILT_IN` 改成 HTTPS 地址。

- **网页尺寸按设计稿**（2026-10-20）：照 macOS 调的长度改由 `style!` 的平台变体给出，网页按网页设计稿取值，界面里不再写死：侧栏品牌行、「新番表 ›」链接、首页舞台与侧栏项的圆角、播放控制的符号大小、字幕 / 倍速 / 画质菜单的宽度、媒体库缩放行、设置表单的分组间距与行高。媒体库的筛选用 `shape: chip`：网页是描边药丸、选中反色带勾，其他平台仍是 30 点胶囊。依赖 Bern 的按平台长度与 `shape: chip`。

## 播放器界面（2026-10-16）

播放器位于 `erika-ui/src/player.rs`，控件位置沿用 `design/next-player.js` / `next.css`。2026-10-22 起，视频在菜单显示、隐藏、暂停以及打开设置时都保持全窗口的等比适配，不再退后、缩小或改变圆角；比例不同的窗口保留黑边。1280 × 800 下的 16:9 画面始终为 `(0, 40, 1280, 720)`，播放设置从顶栏按钮弹出原生气泡，进度条与底部控件的位置和尺寸也不再随设置开关变化。标题、时间轴（包括进度条）、无底色播放按钮及输入框保留黑色柔和阴影；液态玻璃按钮、控制组和胶囊菜单不再被整组覆盖层额外投影，设置气泡使用平台原生材质和阴影。中央播放反馈的阴影限制在 88 点区域内。文字以不透明的白色和浅灰色（`#E6E6EB`）区分主次，播放键两侧的四个图标固定为纯白（`#FFFFFF`，含禁用态；禁用行为不变），发送按钮的禁用文字使用 `#949499`，避免阴影透过半透明字形。“控制层出现时画面退后”设置已移除。较小桌面窗口仍等比缩放控件场景。

- 顶栏、进度条、章节刻度与名称、上一集 / 后退十秒 / 播放暂停 / 前进十秒 / 下一集、字幕音轨菜单、倍速、按模块显示的增强菜单、弹幕快捷设置与发送入口均已接线。2026-10-22 起，章节来自视频容器的实际元数据，按真实起点占总时长的比例显示；点击底部名称或「更多 › 章节…」中的条目会定位到该章节。原有固定章节与星号高峰已移除，无章节的视频不显示这些标记。
- 播放设置气泡包含弹幕、字幕、画面、音频、播放五类；关闭弹幕模块时不显示对应分页。字幕选择、字号、弹幕滚动 / 暂停、透明度、区域和滚动 / 彩色屏蔽可以直接在示例画面中观察。播放器暂停、打开设置或输入时保持控制层可见。气泡不再显示关闭按钮；macOS 上点击气泡外部只收起气泡，不会同时触发下方视频的播放或暂停，下一次点击正常生效。发弹幕输入区由 Rust UI 的 `FocusRegion` 统一声明：首次点击外部只取消焦点并保留未发送草稿，不触发下方播放／暂停；下一次点击正常生效，播放快捷键随之恢复。
- 播放与弹幕设置滑块显示实时数值：音量、不透明度和字幕缩放用百分比，弹幕字号用 pt，速度用秒/屏，偏移标明提前或延后秒数。快捷入口与主设置同步；七个平台声明检查、27 项核心测试和 macOS 构建通过，原生读数与布局已在 macOS 验证。
- 片头／片尾跳过提示使用视频中明确命名为 OP／ED、Opening／Ending、片头／片尾等的章节区间，仅在区间内显示。点击跳到区间结束，保留后续预告并维持原有播放／暂停状态；末尾最多跳到片长前 500 ms。开关持久化，固定「85 秒」已移除。本次数据源为容器章节，旧版的 AniSkip 与弹幕报点推导尚未迁移。31 项核心测试、2 项 liberika 章节测试、七个平台声明检查和 macOS 构建通过；macOS 已实测章节点击、OP／ED 跳过及无章节视频的清空行为。
- 实际视频的时间、轨道与结束状态来自内核；250 ms 时钟负责同步 UI。拖动进度不切换暂停状态。选集使用媒体库同作品的实际文件，或当前文件夹按自然数字顺序排列的视频；上下集、选集和结束连播真正切换来源，末集停止。返回保留侧栏迷你播放器；纯粹模式返回后暂停并保留回到播放器的入口。
- macOS 与 `web_app` 构建通过；核心 11 项测试通过。Bern 的编译器、SwiftUI、Web 和目标能力回归通过，Web 运行时 17 项测试包含拖动期间的引擎更新、负坐标和闲置计时不被播放时钟重置。实际检查了 macOS 1280 × 800 主画框和设置面板、Web 1280 × 800 两种画框坐标、分页、字幕字号、字幕切换、快进与倍速、迷你播放器返回；720 × 480 Web 页面没有横向或纵向溢出。

（2026-10-21 起，打开的文件与链接由 liberika 真播放，字幕、音轨、倍速、超分辨率与时间轴都来自内核，见「播放内核 liberika」；以下是那之前的范围，模块的示例剧集仍是如此。）仍遵守第一阶段的界面模拟范围：剧照代替视频，音频 / HDR / 画质增强等选项只更新状态，文件选择不解析媒体，截图、系统画中画和弹幕匹配给出预览提示。原生控件保留平台外观，纯图标按钮遵循无容器偏好。2026-10-17 已补齐首页舞台 → 播放器、播放器 ↔ 左下角迷你播放器的图片缩放移动动画，并验证快速反向切换、减少动态效果和小窗口恢复；实现与验证范围见扩展记录第 18 项及「播放器缩放转场」。真实视频纹理与其他播放入口的源图配对仍属于后续工作。

## iPhone 适配（2026-10-18）

以设计稿的手机原型（`app.html`，苹果设计、深色，390 × 844）为基准，在 iOS 26.5 的 iPhone 17e 模拟器上逐页量取对齐。布局与内容按原型的点数对齐；导航外观以 iOS 26 系统应用为准：返回是液态玻璃圆钮，顶栏右侧的圆钮为 44 点，相关按钮共用一个玻璃胶囊。

- **页面**：首页、新番、媒体库、搜索、详情、设置列表与各分页、首次引导四步。顶栏由外壳经 `[contributes]` 放进各模块页面留的 `page_header` 等插槽。量取偏差一般在 1 点以内，引导页 1–3 点。
- **横屏播放器**（`player_phone_scene`）：播放时窗口转为横屏（`Window(landscape:)`），`window.short` 选出 844 × 390 的场景。2026-10-22 起，画面始终按窗口等比适配（基准窗口中约 693 × 390，水平居中），菜单及设置不改变视频大小。两侧控件、进度条、顶栏与设置面板 `(544, 56, 284 × 322)` 沿用原型位置并叠在视频上。返回后转回竖屏。
- **迷你播放器**：`TabAccessory`，iOS 26.1 起是标签栏上方的系统附件；内容为 64 × 36 缩略图与进度、标题与集数时间、播放暂停与关闭。附件的位置和宽度由系统决定（比原型的 12 点边距略窄），按系统控件优先保留。
- **模块链接**：首页的「新番表 ›」与「全部 ›」用 `pages.new.show()`、`pages.library.show()` 切到对应页面。
- **时间**：分钟补足两位（`00:07`），秒数向下取整，与原型的 `fmt` 相同；桌面同样生效。

保留原生控件、因而与原型不同的地方：表单行文字为系统的 17 点、分组标题用系统样式；中文字形系统渲染约为 Chrome 的 0.947 倍；播放与进度条为系统控件（滑块、玻璃按钮）。设计文档 6.3 的触控尺寸（中 44、大 50）与手机原型（32 / 42）不一致，目前跟随原型。

为此新增或补全的 Bern 能力：`Row` 按项目宽度排、`Grid(cell_ratio:)`、页面内 `Search`、`Form` / `Section` 版式、`Modal(cover:)`、`Rail(overhang:)`、`ScrollView(open_at:)`、`scroll_origin`、应用自己的 `[contributes]`、`Window(landscape:)`、`window.short`、沉浸窗口铺满屏幕、`TabAccessory`、`pages.<页面>.show()`，以及 iOS 胶囊下拉与分段按钮的版式。各项的平台支持与验证范围见 Bern 的 `Docs/Reference/Platforms.md` 与 `Docs/Design.md`。GTK 于 2026-10-18 补上了 `Stack` 的背景与前景色样式，Linux 版从此可以构建：2026-10-19 起 `bern check` 六个目标都通过，Ubuntu 24.04 虚拟机上运行过（见上面的应用图标记录）。

## Apple TV（2026-10-20）

以设计稿的 TV 原型（`app.html` 选「电视」，`next.css` 的 `.nx[data-dev="tv"]` 一组规则，设计文档 3.1 与 6.2）为基准，用 Bern 新增的 tvOS 目标实现（`erika-ui/src/tv.rs` 与各页面的 `window.tv` 分支）。整个画面是原型的 1280 × 720 场景，放大 1.5 倍铺满 1920 × 1080 的屏幕（`Stack(under_bars: true)` 里的 `ScaleBox`）；遥控器移动焦点。电视用原型的电视字号（`text` 块的 `tv:`）。

- **外壳**：顶部是 tvOS 的系统标签栏：搜索在最前，只是放大镜（`Tab(display: icon)`，读屏仍读「搜索」），之后是首页、新番、媒体库、下载（按启用的模块），页面标签只有文字；每页在标签栏下 80 点开始。右上角（离右边 48、离顶 17，相隔 10）依次是头像、「打开」与设置。「打开」只有打开链接（电视没有文件可选）。播放中收起时，小窗在右下角（300 宽，离右 40、离底 32）。
- **页面**：页边距 56（`.x-page`）。首页舞台 560 × 315，右栏在 x 652，「也在看」行 80 高、缩略图 120 × 68，角上是播放圆钮；新番的一周 500 高，展开的一天 604 宽；媒体库海报从 112 到 230 宽（默认约 154，一行六张），缩放滑块 132 宽，筛选 40 高，字母索引 26 宽；详情与桌面同一布局。
- **搜索**：标题后写着「用遥控器选拼音首字母，或按住遥控器的语音键说出番名」；左边 440 宽的屏幕键盘（A–Z 每行七个 56 × 52，空格、删除、清空两格宽），右边 40 点外是 52 高的搜索框与结果（未输入就列出：番剧海报 96 宽、继续播放、设置、操作）。搜索框也能用系统键盘与听写。
- **设置**：铺满屏幕。左边 300 宽的面板列出各页（46 高、无图标，起始焦点在「通用」），右边是页标题（22 点）与该页的表单，右上角关闭；返回键也关闭。设置的搜索在电视上由搜索页承担（搜索结果有「设置」一组）。
- **播放器**（`player_tv_scene`）：2026-10-22 起画面固定为全屏 `(0, 0, 1280 × 720)`，控件和设置直接叠加。控制条沿用原位置（x 64、宽 1152，打开设置时 x 40、宽 784，y 624、高 56），设置面板仍为 `(848, 52, 392 × 548)`。控制条显示时起始焦点在暂停；隐藏时铺满画面、不画焦点的按钮接住焦点：左右快退快进 10 秒且不唤醒控制条，上下唤醒控制条，按下暂停或继续。弹幕用“发弹幕”按钮打开时间轴位置的输入框。
- **遥控按键**：返回键在详情页关闭详情，在播放器里依次关闭设置面板、回到画框、收起播放器；播放/暂停键切换播放。
- **首次引导**：铺满屏幕的 1280 × 720（左半是 640 × 648 的格纹与 Logo，底部 72 高、按钮 46 高），起始焦点在「开始」，之后每步在「继续」；Logo 用静态图片（tvOS 没有 WebKit）。
- **纯粹模式**：没有标签栏，画框在 `(200, 52, 880 × 495)`，中间是「打开链接…」与「继续上次」，右上角是设置。
- **图标**：`design/brand/erika-icon-export/tvos/Erika.brandassets`，两层的分层图标与 Top Shelf 横幅，由 `build.py` 导出。

验收：2026-10-20，Apple TV 4K（第 3 代）（1080p）模拟器，tvOS 26.5，Xcode 27.0，`bern run --target tvos` 启动，模拟器截图与生成的 CLI（`ui inspect`、`ui activate`、`ui select`、`state`）检查。当天先做了一轮，用户指出搜索、设置等页面显示有问题后，对照原型电视模式逐屏量取重做了一轮（见上）。

### 播放器功能接通（2026-10-22）

- 文件夹、选集、上下集与连播共用真实播放列表；所有打开路径都会加载同名 XML/JSON 弹幕，重新加载同名来源会替换轨道，不重复累加。
- 手动匹配使用原生气泡，按作品搜索、选集确认并保存到媒体库；自动识别受开关控制，支持配置的自定义识别服务。异步回包不会覆盖后来打开的视频或新的搜索。
- 发弹幕校验登录、匹配集数与 1–40 字长度，服务器确认后才显示成功并清空草稿；失败保留草稿。发送中的重复请求会被阻止，写请求不做网关自动重试。自定义来源不支持发送时明确报错。
- 音量、字幕大小、倍速、画质增强、弹幕设置与播放偏好持久化。关闭记忆进度后不恢复或记录位置；硬解开关在下次打开视频时生效。
- 截图、外挂字幕按内核实际结果反馈成功或失败；换片清除上一片外挂字幕文件名。磁力链接进入下载添加流程，不再冒充可播放的视频。
- 全屏按钮和 F 调用 macOS 原生全屏。系统全屏辅助窗口不再阻止播放器闲置隐藏；控制层出现／消失使用 0.22 秒动画，退场期间保持在视频上方。

本轮 macOS 验证包含真实文件选集、字幕加载／关闭、截图文件写出、软件解码、真实 EOF 连播、设置重启恢复及本地模拟服务的自动／手动匹配。37 项核心测试和 3 项 AppKit 回归通过，正式 macOS 构建通过。原生全屏进入／退出已实测；全屏闲置隐藏由 AppKit 回归覆盖，未完成动画逐帧视觉验收。未向真实弹幕服务发布测试评论；其他平台本轮未做实机验收。
